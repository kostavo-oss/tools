# 007 — a UI for plans

**Status:** draft. Phase two.

## Why

A deploy's plan is long, and a terminal shows it one screen at a time, in one colour of detail.
Someone approving a deploy wants to see the whole of it, open the step they care about, and see
that step the way its own tool would show it. *(owner: "a UI for each plan")*

## Requirements

- **R1** — A plan can be opened as a page: every step in order, each with what it would create,
  change, remove or run, and what is decided at apply. *(owner)*
- **R2** — Each step has its own section, and a plugin can supply the detail for it
  ([002/R8](002-plugins.md)): the bundle its resources, by type, with what happens to each. A
  plugin that supplies nothing gets the plan's changes, listed. *(owner)*
- **R3** — Destructive changes can't be missed: they are marked in the step, and counted at the
  top. *(proposed)*
- **R4** — It works from a saved plan file, with no workspace and no credentials — the page shows
  exactly what `apply` of that file would run. *(proposed — it is what `lely show` already
  promises)*
- **R5** — A destroy plan opens the same way. *(proposed)*
- **R6** — After an apply, the same page can show the result: what each step did, and the
  overview of what exists ([004/R7](004-asset-bundle.md)), with links into the workspace.
  *(proposed)*
- **R7** — Nothing secret is on the page. It is built from the plan file, which carries none.
  *(built, for the file)*

## Decided

- **What kind of UI** (was D1): a web page, like `stevin ui` — one self-contained HTML file that
  opens in a browser, can be shared, and can hold a plugin's own view. Not a terminal app.
  *(owner, 2026-10-05)*

## To decide

- **D2 — Reading only, or also doing?** A page that shows a plan is one thing; a page with an
  "apply" button is a server with credentials. *(proposed: reading only)*
- **D3 — How a plugin supplies its view.** As a piece of HTML, which lets a plugin reuse a page
  it already has (stevin's, later), or as data that lely draws, which keeps every step looking
  alike? *(proposed: HTML, inside a frame lely owns)*

## Done when

- A plan with the bundle and a `command` step in it opens as one page: the bundle with its own
  detail, the command with the default.
- The page for a plan file is the same on any machine, with the network off.
- D2 and D3 are answered here.
